Ringkasan Alur dan Logika Aplikasi

1. sales_monitor (Aplikasi Backend - Frappe)

Aplikasi ini berfungsi sebagai backend dan pusat data untuk seluruh proses monitoring sales.

Struktur Data (DocTypes):

  • Sales Visit Plan: Dokumen utama untuk merencanakan kunjungan sales. Isinya adalah siapa sales yang akan pergi, tanggal rencana, dan daftar pelanggan yang akan dikunjungi. Dokumen ini memiliki alur submit dan cancel.
  • Sales Activity Monitoring: Dokumen ini mencatat setiap aktivitas yang terjadi selama kunjungan, dibuat saat "Check In" dan diperbarui saat "Check Out". Menyimpan waktu, durasi, foto, dan koordinat GPS.

Logika & API (api.py):

  • Autentikasi: Fungsi pwa_login khusus untuk login salmon-app ke Frappe.
  • Pengambilan Data Kunjungan: get_sales_visit_plans adalah API utama untuk salmon-app menampilkan jadwal kunjungan.
  • Update Status Kunjungan: submit_visit_update adalah API krusial untuk proses "Check In" dan "Check Out".
  • API Dasbor & Laporan: Menyediakan data teragregasi untuk dasbor dan laporan di salmon-app.

2. salmon-app (Aplikasi Frontend - React/TypeScript)

Ini adalah Progressive Web App (PWA) yang digunakan oleh tim sales di lapangan dan sepenuhnya bergantung pada API dari sales_monitor.

Alur Aplikasi:

  1. Inisialisasi & Login: Aplikasi memuat konfigurasi URL backend, lalu pengguna login melalui endpoint pwa_login.
  2. Navigasi: Setelah login, pengguna diarahkan ke dasbor dan dapat bernavigasi ke halaman lain seperti Jadwal, Laporan, dll.
  3. Dasbor: Menampilkan ringkasan data dari berbagai API dasbor di backend.
  4. Jadwal & Check-in/out: Menampilkan jadwal dari get_sales_visit_plans. Proses check-in/out memanggil API submit_visit_update dengan data relevan (GPS, foto).
  5. Input Rencana: Sales dapat membuat rencana kunjungan baru melalui halaman "Visit Planner" yang memanggil API create_sales_visit_plan.

Kesimpulan Alur Terintegrasi

  1. Perencanaan: Rencana dibuat di Frappe atau melalui salmon-app.
  2. Eksekusi: Sales membuka salmon-app di lapangan, login, dan melihat jadwal.
  3. Check-in: Sales tiba di lokasi dan melakukan "Check In". Aplikasi mengirim data ke backend untuk membuat catatan aktivitas.
  4. Check-out: Sales selesai, mengambil foto, dan "Check Out". Aplikasi mengirim data lagi untuk melengkapi catatan aktivitas.
  5. Monitoring: Manajer memantau progres secara real-time melalui laporan di Frappe.

Sistem ini memisahkan dengan jelas antara logika bisnis dan data (sales_monitor) dengan antarmuka pengguna dan interaksi lapangan (salmon-app).
